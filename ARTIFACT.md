# PhishArmor — Artifact Package

Code and data-generation scripts for *"PhishArmor: Adversarial Robustness for
Phishing Detection as an Economic Problem."*

Every numeric claim in the paper is machine-audited against a JSON artifact in
`results/`. The table below maps each claim to the command that produces it.

---

## 1. Environment

Developed and run on **macOS 15 (Darwin 25.3.0), Apple Silicon (arm64)**, Python
**3.14.6**. Key versions: `torch==2.13.0`, `torchvision==0.28.0`, `numpy==2.5.2`,
`scipy==1.18.1`. Full pin list in `requirements-lock.txt` (93 packages).

```bash
python3 -m venv .venv && ./.venv/bin/pip install -r requirements-lock.txt
```

**On device selection.** MPS is available on this hardware but the lexical
evaluations are pinned to **CPU**, deliberately. `reliance()` is a pure
input-gradient computation, and on MPS it returned all-NaN for the baseline arm
while the defended arms stayed finite; averaging over seeds propagated that
silently, and a *completed* run reported both H1 and H2 as `nan`. CPU reproduces
H1 = +0.201 ± 0.031 and H2 = +0.774 ± 0.045. The harness now raises on non-finite
reliance rather than averaging it. The visual encoder also runs on CPU
(`DEV = "cpu"` in `phishnet/eval/phishpedia_crucible.py`).

Training is memory-bandwidth bound, not thread bound: 4 vs 8 torch threads
measured 0.551 vs 0.562 s/step. Expect **~16 min per training arm** on an idle
M-series machine; contention from a background VM roughly doubled that in our
runs.

### Reproduction status

Three of these entry points (`lexical_correlations`, `dropout_sweep`,
`seeds_stats`) were written after the fact, because the artifacts they produce
had originally been generated by ad-hoc code. Each has since been **executed and
verified to regenerate its committed artifact exactly**:

| Script | Verified against | Result |
|---|---|---|
| `seeds_stats` | `phishpedia_seeds_stats.json` | byte-identical |
| `lexical_correlations` | `h1_h2_cpu.json`, `per_feature_evasion_cpu.json` | byte-identical |
| `dropout_sweep` | `dropout_sweep.json` | all 38 fields exact, incl. sds |

Recovering the sweep's configuration required inference: the reconstruction
initially used 3 seeds and did not match. The committed artifact's `resist`
values are exact integers over 600, which identifies 5 seeds x 120 CTE samples;
with that configuration every field reproduces. The seed count is now pinned in
the script.

`seeds_stats` is pure post-processing and runs in seconds, so §4.3's entire
statistical apparatus — every p-value, t-statistic and effect size — can be
checked from the committed `phishpedia_seeds.json` **without retraining
anything**. This is the cheapest meaningful verification in the package.

**Runtime.** The 13-seed replication is 39 training arms at ~16 min each,
≈10 hours total. It **checkpoints after every seed** and skips completed seeds on
restart, so it can be run in stages:

```bash
python -m phishnet.eval.phishpedia_seeds --seeds 0 1 2   # then 3 4 5, etc.
```

## 3. Validity gates (standalone)

The three experiment-validity gates are a stated contribution of the paper and
are independently executable. They reject two of our own experiments.

```bash
python -m phishnet.eval.competence_gate          # runs all three against our own runs
python -m pytest tests/test_pipeline.py -q       # 16 tests, incl. 5 gate regressions
```

The regression tests pin the exact failures the gates caught: a baseline at the
noise floor *and* less robust than untrained ImageNet features; a colour-dominated
corpus with inverted attack ordering; and a split with 37.3% duplicate crops.

## 4. Data acquisition

### 4.1 Visual corpus — known upstream constraint

The visual corpus is 3,162 deduplicated logo crops harvested from the Phishpedia
benchmark (Google Drive id `12ypEMPRQ43zGRqHGut0Esq2z5en0DH4g`).

```bash
python scripts/harvest_phishpedia.py --workers 24
```

**Note for artifact reviewers.** The source archive is **19.3 GB**, larger than
free space on our development machine, so nothing is downloaded whole: the script
parses the ZIP64 central directory and issues HTTP **range requests** for only the
members it keeps (~3.3 GB for the harvested subset). Two consequences you should
expect:

- **Google Drive enforces a rolling 24-hour quota on this file id.** If the
  script fails with a quota or `FileURLRetrievalError` message, you have hit the
  upstream limit, not a bug — it blocked us for a full day during this work. Wait
  and retry. `gdown` fails *permanently* on this id even when the file is
  downloadable; the script's raw-`curl` confirm-token path is the working route.
- The harvest is **resumable**. Screenshot downloads skip files already on disk
  and `info.txt` records are cached in `data/phishpedia/info_cache.json`.

14.27% of the archive's samples carry an empty `yolo_coords.txt` (no logo
detected). This is a property of the dataset, not a failure, and is the basis of
the 85.7% recall bound in §6.1.

### 4.2 Lexical corpus — verified from processed features only

The lexical detector trains from the 30 hand-designed URL features in
`phishnet/features/lexical.py`, extracted via `extract_batch()` inside each eval
script.

**We state this limit plainly:** the lexical evaluations are deterministic and
reproducible *given the URL corpus*, but the upstream corpus-assembly pipeline
(`phishnet/data/datasets.py`, which draws on external URL feeds) has **not been
verified for clean-checkout execution** on a machine other than ours. Feed
availability and composition may drift. Reviewers wishing to confirm the *numbers*
rather than the data pipeline should compare against the committed JSON artifacts
in `results/`, which is what the paper's audits check.

## 5. Reproducing the manuscript

The built PDF is deliberately **not** shipped in the archive; building it is
part of the artifact check. Verified from a clean extraction of the release
tarball: 18 pages, with the assembled manuscript and rendered HTML
byte-identical to the development tree.

```bash
python scripts/assemble_phisharmor.py                     # section drafts -> manuscript
python scripts/build_paper.py --source paper/phisharmor_manuscript.md \
    --out-html paper/phisharmor.html --out-pdf paper/PhishArmor_paper.pdf
```

The PDF step shells out to headless Chrome. The script searches `PATH` and the
usual macOS/Linux install locations; set `CHROME_BIN=/path/to/chrome` if yours
is elsewhere. Without a browser the HTML is still written and only the PDF step
is blocked.

## 6. Known limitations

1. **Cost table encodes judgement, not telemetry.** Prices are grounded in 2026
   attacker economics but assigned by us. Mitigated by rank-linear weighting
   (ordering only) and a ±30% weight-perturbation sweep that moves median CTE
   only between 0.222 and 0.225. This is a sensitivity analysis, not a hypothesis
   test.
2. **Top-1 logo box is a noisy proxy.** Crops use the highest-confidence RCNN
   region, which is a logo *candidate*, not verified ground truth. Manual
   inspection found roughly one in six crops to be a non-logo region such as a
   cookie banner.
3. **The mechanism margin is small.** §4.3.4's +0.014 (p = 0.006) required 13
   seeds; at 5 seeds the same quantity read +0.0099 with p = 0.12. Fewer seeds
   will not reproduce the result, and we report the power analysis rather than
   presenting the effect as robust to small n.
